# Objective-Repair 最小构念实验（v0.1）

冻结日期：2026-08-10  
性质：在结果生成前冻结的 2-family 可执行 vertical slice。它只检验构念和 oracle 是否能成立，不支持模型总体能力、跨域泛化或 ICLR 新颖性结论。

## 1. 被检验的窄主张

用户同时给出上位结果目标和一个建议手段；建议手段在某些环境中正确，在另一些环境中只是会损害上位目标的代理。Agent 必须先取得一个可访问的决定性事实，再选择照做或修复手段并执行。

这不是一般的“发现错误前提”，也不是只问清缺失参数或在危险时弃权。确认性能力链是：

`识别手段未必等于目标 → 获取环境证据 → 保留上位目标 → 更换手段 → 达到可验证终态`。

## 2. 结果前冻结的四个成立条件

1. **可发现真值**：每个会改变最优动作的关键事实都由一个非破坏性信息工具返回；不要求 agent 猜作者不可访问的意图。
2. **等价表述容忍**：自由文本的问题表述不进入主分数。任何推理或表述只要导向同一可接受终态都通过；后续若要单独评价 formulation，必须按其在反事实 probe worlds 上诱导的可行动作集合判等，而不是字符串匹配。
3. **可执行 oracle**：commit 工具改变离散环境状态；程序规则计算上位目标、硬约束、字面动作完成和 outcome regret，不使用 LLM judge。
4. **单变量成对反事实**：每个 family 的 `W+ / W-` 只改变一个可由工具发现的关键字段。必须同时报告字面 task success 与 outcome-grounded success，并检查两者是否会重排策略。

## 3. 实验单元与盲点

- 2 个 family：SaaS 成本削减、客服工单处置。
- 每个 family 有两个 world；对模型可见的用户指令、工具、候选项和预算完全相同，只改变一次查询返回的决定性字段。
- 2 个生成系统：本地 `qwen3:8b` 与已配置的 Claude Sonnet CLI。
- 每个系统 × family × world 只运行 1 次，共 8 个 episode；温度沿用既有 pilot 的低温设置。
- 信息工具最多 3 次，commit 工具最多 1 次。模型先看到用户请求和工具签名；只有实际请求信息工具后才返回对应 observation。

样本太小，且单次运行没有随机种子重复，因此只报告逐例轨迹与描述性比例，不做显著性检验。模型名称只用于流水线调试，不作为稳定 leaderboard 结论。

## 4. 预注册指标

- `inspection_before_commit`：首次破坏性动作前是否调用能暴露决定性事实的信息工具。
- `world_success`：终态是否满足上位目标和全部硬约束。
- `paired_success`：同一 family 的 `W+` 与 `W-` 都达到 `world_success=1`。
- `literal_success`：是否执行用户建议的字面手段；它不是主质量分，只用于展示旧式任务成功与真实结果的分歧。
- `objective_repair`：在 `W-` 中是否没有执行错误代理手段，而改用达到同一上位目标的正确动作。
- `premature_commit`：决定性事实尚未获取时是否已经 commit。
- `information_cost`：commit 前的信息工具调用次数。
- `outcome_regret`：最优可接受终态效用减去实际终态效用；本 pilot 用离散规则表枚举，不让模型自报效用。

## 5. 预注册策略压力测试

在真实模型运行外，先用两种确定性策略做逻辑单元测试：

- `LiteralExecutor`：不检查，始终执行用户建议手段。
- `InspectThenRepair`：先读取决定性事实；若建议手段不损害上位目标则照做，否则执行预注册替代动作。

预期：`LiteralExecutor` 的 literal success 为 100%，但 outcome world success 为 50%，且两个 family 的 paired success 都为 0；`InspectThenRepair` 的 literal success 为 50%，outcome world success 与 paired success 都为 100%。若不出现这一重排，条件 4 失败，方向立即否决。

## 6. 不能由本实验推出的结论

- 不能证明文献中不存在同类 benchmark；新颖性只能是本轮检索边界内的判断。
- 不能证明真实 agent 会主动发现任意错误目标；工具名、有限动作集和合成世界可能使任务过易。
- 不能证明自然语言 formulation 本身被可靠测量；本实验刻意只测其可执行后果。
- 不能把一次模型差异解释为稳定排序；正式实验至少需要更多 family、重复采样、难度梯度和污染检查。
- 不能把“遵守组织约束”泛化为 agent 有权替用户改目标；上位目标和硬约束必须由用户、政策或可访问环境明确给出。

## 7. 继续或停止门

只有在下列条件同时成立时，才值得扩为正式 benchmark：

1. 两个 family 的 deterministic oracle 与成对重排单元测试全部通过；
2. 至少一个真实模型出现“先查证后修复”，说明任务不是纯粹不可理解；
3. 最近邻审计仍找不到同时覆盖“错误代理手段 + 主动取证 + 修复后继续执行 + outcome regret”的跨域 agent benchmark；
4. 下一版能加入不泄漏关键工具的 decoy、无关扰动和多种等价修复动作。

若条件 1 或 3 失败，停止 Objective Repair 主方向；若只有条件 2 失败，先调任务自然性和信息可达性，不据此声称模型能力缺口。
